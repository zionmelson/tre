# Protocol Decoder Plan

## Goals

- Preserve per-protocol quirks (pricing models, ticks, bins, oracle slots) without forcing a generic swap schema.
- Guarantee every field we rely on is decoded deterministically from the on-chain IDL definition.
- Catch regressions quickly when upstream IDLs change.

## Architecture Overview

1. **Manifest + Registry**
   - `config/protocols.json` remains source of truth mapping CoreCast program IDs to protocol slugs.
   - Registry now stores, per slug:
     - Static pool template bytes (already generated by `pools_static`).
     - A protocol-specific strategy/decoder handle (e.g., `Arc<dyn ProtocolStrategy>`).
2. **Protocol Modules**
   - Each protocol gets its own module (e.g., `strategy/whirlpool.rs`, `strategy/lb_clmm.rs`).
   - Module defines bespoke structs for pricing data, oracle references, tick/bin math, etc.
   - Implements a minimal trait, for example:
     ```rust
     pub trait ProtocolStrategy: Send + Sync {
         fn evaluate(&self, opp: &Opportunity, raw_ix: &[u8]) -> Option<BundleRequest>;
     }
     ```
   - No shared `SwapEvent`; each implementation owns its internal types and conversions.
3. **Stage Flow**
   - Stage 0 tags opportunities with the protocol slug via the registry (already implemented).
   - Stage 1 resolves the slug → protocol strategy and forwards the opportunity + raw bytes.
   - The strategy module decodes, runs heuristics, and optionally emits a bundle.

## Decoder Implementation Checklist (per protocol)

- [ ] Mirror all relevant instruction layouts from the IDL (discriminator, args, account order).
- [ ] Enumerate fixed-point formats (e.g., Q64.64) and provide helpers for raw + human-readable values.
- [ ] Map every pricing-critical field: price, fee tiers, ticks/bins, oracle pubkeys, partner fees, etc.
- [ ] Validate account count/order to avoid misaligned parsing when programs upgrade.
- [ ] Document dependencies (e.g., requires companion oracle account).

## Validation Strategy

1. **Golden Fixtures**
   - Capture representative transactions per protocol (mainnet data or simulated instructions).
   - Store as `.json`/`.bin` fixtures under `tests/fixtures/<protocol>/`.
   - Unit tests feed raw instructions into the decoder and assert every field (amounts, ticks, oracle references) equals the fixture metadata.
2. **IDL Drift Detection**
   - Record current IDL version hash per protocol (metadata `version` + file hash) in the module.
   - Add a CI check that compares the committed hash against the on-disk IDL; fail if mismatched until decoders are updated.
3. **Tracing Hooks**
   - When decoding fails (bad discriminator, length mismatch), log the protocol slug + reason so Stage 1 can drop safely with observability.

## Upgrade Playbook

1. Pull latest IDL for the protocol and drop it into `idls/pools`.
2. Run `cargo xtask diff-idl <protocol>` (future helper) to view structural changes.
3. Update the protocol module structs/decoders accordingly.
4. Refresh fixtures (capture new transactions) and rerun tests.
5. Bump the stored IDL hash/version in the module and add a manifest entry if new programs were introduced.

## Optional Tooling

- **IDL Introspection CLI**: small utility that lists instructions/types per IDL (script already prototyped) to sanity-check coverage.
- **Decoder coverage report**: enumerates all discriminators in the IDL vs. the ones implemented; warns on gaps.
- **Registry smoke test**: spins through every manifest entry, ensures a decoder + template exist, and runs a minimal decode against canned data.

Following this plan keeps each protocol siloed while guaranteeing we never miss important pricing fields when decoding swaps.
